# 問い合わせ管理Demoサイト

## 概要

問い合わせの受付、管理者による一覧確認、詳細確認、ステータス変更、返答内容の保存を行うためのDemoサイトです。

現時点では、HTML / CSS / JavaScript のみで構成した静的サイトとして作成しています。
データ保存にはブラウザの `localStorage` を使用しており、DBやサーバーサイド処理はまだ使用していません。

GitHub Pagesで静的サイトとして公開し、問い合わせ管理システムの画面構成と基本操作フローを確認できる状態にしています。

次の段階では、Laravel + DB構成へ拡張し、問い合わせデータをサーバー側で管理できる形にする予定です。

## 公開URL

```text
https://yuyamitsu.github.io/inquiry-demo/
```

## 作成目的

これまでの「機能を作る」段階から、次のステップとして「設計して作る」ことを目的に作成しています。

問い合わせ管理を題材に、画面構成、管理対象データ、操作フロー、検索条件、ステータス管理などを整理し、段階的にDemoサイトとして実装しています。

基本的な流れは以下の通りです。

```text
問い合わせ受付
↓
問い合わせ登録
↓

↓
問い合わせ詳細確認
↓
ステータス更新
↓
管理者返答
↓
検索・絞り込み
```

## 画面構成

### 1. 問い合わせフォーム

ファイル：

```text
index.html
```

利用者が問い合わせ内容を入力する画面です。

入力項目は以下の通りです。

| 項目      | 内容                  |
| ------- | ------------------- |
| お名前     | 問い合わせした利用者名         |
| メールアドレス | 返信先メールアドレス          |
| 件名      | 問い合わせのタイトル          |
| カテゴリ    | 質問 / 相談 / 不具合 / その他 |
| 問い合わせ内容 | 問い合わせ本文             |

### 2. 管理者一覧画面

ファイル：

```text
pages/admin-list.html
```

登録された問い合わせを一覧で確認する画面です。

表示項目は以下の通りです。

| 項目    | 内容         |
| ----- | ---------- |
| ID    | 問い合わせID    |
| 件名    | 問い合わせタイトル  |
| 名前    | 問い合わせ者名    |
| カテゴリ  | 問い合わせ分類    |
| ステータス | 対応状況       |
| 受付日時  | 登録日時       |
| 詳細    | 詳細画面へのリンク  |
| 削除    | 問い合わせ削除ボタン |

一覧画面では、問い合わせ件数のサマリー表示、検索・絞り込み、サンプルデータ追加、全データ削除も行えます。

### 3. 管理者詳細画面

ファイル：

```text
pages/admin-detail.html
```

問い合わせ内容の詳細確認と、管理者対応を行う画面です。

管理者は以下の操作ができます。

* 問い合わせ内容の確認
* ステータス変更
* 返答内容の入力
* 対応内容の保存

## ステータス

問い合わせの対応状況として、以下のステータスを使用しています。

| ステータス | 意味              |
| ----- | --------------- |
| 未対応   | まだ管理者が対応していない状態 |
| 対応中   | 管理者が確認・対応している状態 |
| 回答済み  | 利用者への返答が完了した状態  |
| クローズ  | 対応完了として終了した状態   |

## 入力チェック

問い合わせフォームでは、JavaScriptによるフロント側入力チェックを実装しています。

| 項目      | チェック内容       |
| ------- | ------------ |
| お名前     | 必須、50文字以内    |
| メールアドレス | 必須、メールアドレス形式 |
| 件名      | 必須、100文字以内   |
| カテゴリ    | 必須           |
| 問い合わせ内容 | 必須、1000文字以内  |

エラーがある場合は、各入力項目の下にエラーメッセージを表示します。

現時点では、利用者の入力ミスを送信前に知らせるためのフロント側チェックとして実装しています。
サーバー側のバリデーションは、Laravel + DB化する次段階で実装する想定です。

## サンプルデータ機能

管理者一覧画面に、サンプルデータ追加機能を実装しています。

これにより、手入力を行わずに以下の動作を確認できます。

* 問い合わせ一覧表示
* 詳細画面への遷移
* ステータス表示
* 検索・絞り込み
* 件数サマリー
* 削除処理

また、検証用データをリセットできるように、全データ削除機能も実装しています。

## 構成方針

`index.html` はGitHub Pagesで最初に表示されるトップページとして、リポジトリ直下に配置しています。

管理者側の画面は `pages` ディレクトリにまとめています。

CSS、JavaScript、画像などの静的ファイルは `assets` ディレクトリ配下にまとめ、画面ファイルと共通アセットを分離しています。

これにより、画面ファイル・スタイル・スクリプトの役割を分けて管理しやすい構成にしています。

## データ保存について

現在はDBを使用せず、ブラウザの `localStorage` に問い合わせデータを保存しています。

そのため、問い合わせデータはサイトを開いた利用者のブラウザ内にのみ保存されます。

```text
自分のブラウザで登録した問い合わせ
→ 自分のブラウザに保存される

他の人のブラウザで登録した問い合わせ
→ その人のブラウザに保存される
```

現時点では、複数ユーザー間で問い合わせデータを共有する構成ではありません。

## Laravel + DB化について

次の段階では、現在 `localStorage` で保持している問い合わせデータをDB保存に置き換えます。

初期実装では、ローカル開発環境で扱いやすいSQLiteを使用して、LaravelのModel、Migration、Controller、BladeによるDB保存の流れを作成します。

実運用や実務に近い構成を想定する段階では、MySQLへの移行を検討します。

### DB方針

| 段階   | DB     | 目的                    |
| ---- | ------ | --------------------- |
| 初期実装 | SQLite | ローカル開発でDB保存の流れを確認する   |
| 実務想定 | MySQL  | 複数ユーザー利用・本番運用に近い構成にする |

SQLiteとMySQLで、LaravelのModel、Migration、Controllerの基本的な考え方は大きく変わりません。
そのため、まずはSQLiteでDB保存の流れを作成し、必要に応じてMySQLへ切り替える想定です。

## Laravel化する場合の対応イメージ

## 動作確認手順

### 1. 問い合わせを登録する

`index.html` を開き、問い合わせフォームに以下のような内容を入力します。

```text
お名前：山田 太郎
メールアドレス：yamada@example.com
件名：料金について
カテゴリ：質問
問い合わせ内容：料金プランを教えてください。
```

送信後、管理者一覧画面へ遷移します。

### 2. 入力チェックを確認する

問い合わせフォームで以下の内容を確認します。

* 未入力時にエラーが表示されること
* メールアドレス形式が不正な場合にエラーが表示されること
* お名前が50文字を超える場合にエラーが表示されること
* 件名が100文字を超える場合にエラーが表示されること
* 問い合わせ内容が1000文字を超える場合にエラーが表示されること
* 正しい内容を入力した場合に登録できること

### 3. 一覧画面で確認する

`pages/admin-list.html` で、登録した問い合わせが一覧に表示されることを確認します。

また、件数サマリーに問い合わせ件数が反映されることを確認します。

### 4. サンプルデータを確認する

管理者一覧画面でサンプルデータ追加ボタンを押し、複数の問い合わせが一覧に追加されることを確認します。

あわせて、全データ削除ボタンで検証データを削除できることを確認します。

### 5. 詳細画面で確認する

一覧の「詳細」を押し、`pages/admin-detail.html` に遷移します。

問い合わせ内容が表示されることを確認します。

### 6. ステータスを変更する

詳細画面でステータスを変更し、返答内容を入力して保存します。

例：

```text
ステータス：対応中
返答内容：お問い合わせありがとうございます。確認いたします。
```

保存後、一覧画面に戻り、ステータスが変更されていることを確認します。

### 7. 検索・絞り込みを確認する

一覧画面で以下の検索を確認します。

* キーワード検索
* ステータス絞り込み
* カテゴリ絞り込み
* 検索条件リセット

### 8. 削除を確認する

一覧画面の削除ボタンを押し、対象の問い合わせが削除されることを確認します。

### 9. レスポンシブ表示を確認する

ブラウザ幅を狭めた状態やスマートフォン表示で、以下を確認します。

* フォームが画面幅に収まること
* 検索条件が縦並びになること
* サマリーカードが崩れないこと
* 一覧テーブルが横スクロールできること
* 詳細画面の項目が見やすく表示されること
